### GitHub 工具贴图

标题先写读者要完成的具体任务或熟悉场景，再写工具能提供的可见结果；项目名用于识别，默认放在标题后半句，不让仓库名或 Star 数占据标题钩子位置。优先使用“读者任务/输入 + 可见结果”或“熟悉场景 + 工具解决的阻碍”。技术机制（如 HTML、Agent、逐帧渲染）只有在它本身就是目标读者关心的结果时才进入标题，否则放到正文说明。用卡片计划和事实基座中已有的任务与结果；没有事实支持时直接用任务表达，不虚构普遍痛点。

配文围绕一个具体任务组织，必须覆盖：读者任务/痛点、项目能提供的结果、1–2 个关键亮点、必要的运行前提/风险边界、一个明确获取入口。不要把 README 改写成项目介绍长文；只保留一个主任务场景和最多两个亮点，不同时罗列多个用途、所有功能或适配器、完整命令链、版本/许可、项目阶段和泛泛适用人群。次要信息优先留给卡片页。

正文默认以 180–320 个中文字符为聚焦目标，不计标题、URL 和话题标签。此范围用于控制信息取舍，不得为卡字数删掉必要的运行条件、风险边界或“基于项目文档整理，未实际运行”说明；必要时可稍长，超出时先删次要背景和功能介绍。

获取地址独立成行，只提供 GitHub 仓库主页。不要再附加 Releases/下载入口链接；仓库主页中已有安装和版本说明。准确标注为“项目主页”，不得把仓库主页称为安装包直链，也不得编造 URL。
