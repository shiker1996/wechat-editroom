# 技术深解

让读者带走一条可验证的技术知识、一笔能复算的账或一个有依据的判断；开头和结构仍优先争取点击与完读，不把文章写成技术报告。

## 输入输出

编排模式读取 `01-personal-materials.md`、`02-outline.md`、`03-titles.md`，写入 `04-draft.md`。独立调用时要求提供主题、角度、目标读者、事实来源和技术数据。

只使用事实基座允许的事实；读取发布主张登记，`restricted_claims` 只能按归因和限定方式出现。估算值必须标为估算，并写出假设、公式、单位和数据来源。

## 写作

先读取流量规划和 `material_brief`，所有文章都以点击、完读和可复述结论为基线；用 `opening_hook` 进入具体问题，明确技术动作影响谁、读者后果和成本/责任冲突，再决定需要解释的最小原理；`reader_action` 应落到可复算的判断依据，`evidence_boundary` 约束估算和比较，不能用技术细节回避素材中的现实影响。读者收益按 `reader_value_placement` 放置，不能机械增加“行动建议”章节。该技能默认 `writing_stance=analysis`，但必须服从运行时 overlay；overlay 不得放宽数字、性能、成本和事实门禁。

1. 列出理解本文所需的最少概念，并用一句准确类比解释；不要用类比替代原理。
2. 说明技术解决的问题、关键机制和限制条件。
3. 对重要指标做换算：展示公式、输入、单位和结果，解释它对真实使用意味着什么。
4. 选择公平参照系，与旧方案或竞品比较相同口径、相同条件下的差异。
5. 区分已测结果、厂商宣称、作者估算和作者判断。涉及融资、估值、上市、违法、造假或公司/个人负面评价时，不能把传闻、摘要或模型推断写成确定事实。

结构通常为：具体问题或反差 → 最小前置知识 → 原理/算账/对比中的必要部分 → 条件化判断；普通成稿安排 3–5 个 H2。根据材料删减旁支，不强行凑齐无关章节；前 200 字内交代读者为什么值得继续看，正文至少两次推进。

关键事实和数字就近引用。至少嵌入一个作者素材锚点。核心关键词自然出现在前 200 字。避免“性能提升 80%”却不写基线，也避免把参数量直接等同于能力。

正文遵守总契约的可见字符范围。复杂技术材料优先减少旁支概念和重复案例，不省略公式假设、单位、比较口径与限制条件，也不为了显得专业牺牲开头和完读节奏。

## 自检

确认读者能复算至少一个关键结果；比较口径一致；每个数字都有来源或估算标记；已说明限制、反例或适用边界；标题、摘要和前 200 字没有未经核验的高影响数字、动作或负面结论；正文不超过 2000 个可见字符。
