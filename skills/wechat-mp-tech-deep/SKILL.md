# 技术深解

用必要的技术原理解释简报提出的问题和判断。让读者理解关键机制、适用条件或实际影响，不把文章写成术语汇编或技术报告。

## 本阶段任务

使用成稿调用提供的锁定简报、主题/临时标题、事实基座和发布主张登记，写出完整初稿。简报锁定要回答的问题和判断，不提供章节大纲；自行选择最易解释清楚的概念顺序和文章结构，不生成或等待独立大纲。不要另行扩写教程、对比报告或行动清单。

## 写作要求

- 只解释回答锁定问题所需的技术概念。先用准确的日常语言说明，再补必要细节。
- 公式、成本或性能计算只在简报的问题确实需要且事实基座提供足够数据时进行；写明假设、单位和口径。数据不足就不算，不用估算填空。
- 只有存在可比数据且能增加对核心判断的理解时，才与旧方案或竞品比较；保持相同口径，不猜测能力差异。
- 区分实测结果、厂商说法、事实和作者判断。保留有事实依据的推断，不把观点改成事实，也不重复添加免责声明。
- 按核心问题、事实顺序和解释难度决定章节和篇幅，不强制 H2 数量、计算结果、类比、反方段落或作者素材。
- 删除与主线无关的旁支知识，保留读者理解结论所需的限制条件。

## 事实边界

事实只能来自事实基座授权的内容。按运行时契约处理 `verified`、`disputed`、`opinion`、`unverified` 和 `restricted_claims`；不补造参数、测试结果、公式输入、来源或作者实践。

## 输出

只输出完整 Markdown 文章，第一行是唯一 H1；使用调用提供的标题，不附写作说明或审稿报告。
