# 深度分析写作

围绕一个可辩护的核心判断写作，不把材料整理误当成分析。运行时接收 `writing_stance` overlay；本技能负责行业、职场或社会事件的事实—机制—利益关系结构，不为不同立场复制技能。

## 输入输出

编排模式读取 `01-personal-materials.md`、`02-outline.md`、`03-titles.md`，写入 `04-draft.md`。独立调用时要求提供主题、角度、受众和可核验材料。

## 分析框架

先读取流量规划和 `material_brief`，把 `click_mechanism`、`opening_hook` 和 `conflict` 变成开头与正文推进，把 `reader_consequence` 作为读者收益的落点；所有文章都以点击、完读和可复述判断为基线，`content_role` 只改变包装侧重。`baseline_change` 只能在事实基座有支持时使用，`evidence_boundary` 约束因果和反方表述。读者收益根据 `reader_value_type` 和 `reader_value_placement` 实现，故事或观点型文章优先融入正文，不强行增加清单章节。素材成熟度不是结论，也不能掩盖证据缺口。

- 读取上游 `distribution_lane` 与 `reader_stake`；前 50–80 字用具体人物、场景、数字或反差进入，前 200 字内给出作者判断和本文要解释的矛盾。
- 识别主要参与方、各自激励、权力或资源约束，以及谁承担成本。
- 将相关性与因果性分开；无法证明因果时使用更克制的表述。
- 普通成稿安排 3–5 个 H2 推进主线；“事实 → 机制 → 判断 → 反例/边界”只是思考顺序，不是固定排版模板。
- 至少安排两个上游标记的信息、情绪或判断升级点；不重复新闻摘要，不把最有力的判断拖到结尾。
- 职场或平台事件说明谁获得收益、谁承担成本，以及普通读者可能受到的影响；情绪可以是入口，但不能替代证据。
- 只有 `reader_value_placement=standalone_h2` 时才单独写清单、决策框架或行动建议；否则把收益融入人物、机制、冲突或结尾。
- 结尾回收标题承诺，留下具体判断、条件边界或可讨论的问题。

关键事实按运行时 `writing_stance` 和 `visible_citation` 策略归因：同一 `source_group_id` 的连续主张可以集中归因，不将审计字段机械写成每句来源提示；`report` 仍保持较高来源可见密度。不将匿名爆料、单方说法或研判假设写成确定事实。`restricted_claims` 只能按照主张登记的归因和限定方式出现。涉及 IPO、上市、估值、融资、违法、造假、压榨或个人/公司名誉时，必须说明谁提出主张、证据是否直接、是否有回应；证据不足时收窄为对公开现象或判断方法的分析。至少嵌入一个真实作者素材锚点；推断的素材只能写成作者当前判断。允许口语、停顿和适度题外话，但不强制每 300 字造金句。

“事实 → 机制 → 判断 → 反例/边界”是思考顺序，不是排版模板：判断与边界必须融进叙述，禁止“作者判断：”“反方边界：”这类元话语标签；事实与观点的区分靠行文而非标注。`opinion` 立场尤其不要反复解释“这是观点”“不是事实”，只在单方或未核实主张处保留自然限定。结尾不写“关注账号”“拭目以待”一类模板句，必须落回本文的具体判断。

## 自检

确认文章只有一个主线；标题、前 200 字、冲突推进、读者收益和结尾回收彼此一致；观点有事实和机制支持；呈现了最强反方解释；没有把公司公关说法、匿名爆料或模型推断当事实；没有连续背景堆积、过早说完结论或强行增加清单章节；全文遵守总契约字数范围。需要压缩时优先删除重复背景、次要案例和同义结论，不删除关键事实、边界、来源、人物细节和有效判断。
