# 技术热点写作

解释一个已核验的技术事件、产品变化或公司动态为什么值得目标读者关注。围绕简报中的判断展开，不把新闻复述扩成泛泛的行业趋势。

## 本阶段任务

使用成稿调用提供的锁定简报、主题/临时标题、事实基座和发布主张登记，写出完整初稿。锁定简报规定核心问题、角度和读者影响，不提供章节大纲；根据事实关系和论证需要自行组织结构，不生成或等待独立大纲。不要重做选题、流量规划或读者收益规划，也不要偏离简报另开分析任务。

## 写作要求

- 从简报锁定的事件或问题进入主题，说明必要背景和它对目标读者的实际影响。
- 只保留理解判断所需的技术细节；不要为了证明专业而讲完整原理、强行类比或补充无关参数。
- 按事实关系和论证需要自然组织事实、解释和判断；不按新闻条目逐条堆叠，也不要求每节套同一种结构。
- 有事实依据的作者推断可以直接表达为判断。区分推断与已确认事实，但不要求重复解释边界或给每个观点句加限定。
- 只有锁定问题和事实材料确实需要时才讨论反方、成本、行动建议或后续观察信号，不为完整感强行加段落。
- 标题承诺、关键词和读者影响以已锁定简报为准，不在正文重做 SEO 或包装。

## 事实边界

事实基座是已有证据台账，不是唯一来源。写作时主动联网核验关键事实、数字、回应和适用规则，可据可追溯的搜索结果补充事实；新事实必须自然归因并链接实际检索来源，后续审稿将复核并记录。未确认主张收窄或准确归因；不按模型记忆补造数字、引语、产品能力、来源或公司动机。关键事实按来源簇自然归因，避免逐句重复来源和风险说明。

## 输出

只输出完整 Markdown 文章，第一行是唯一 H1；使用调用提供的标题，不附写作说明或审稿报告。
