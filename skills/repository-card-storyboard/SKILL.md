# 工具图文故事板

只负责 `social-tool` 入口的 `repository` 内容。故事板把已核验的仓库事实转换成“读者任务—可见结果—项目能力—上手路径—适用边界”，不把项目介绍升级成技术趋势或深度文章。选项目和写页面时先找一条能由 README/演示/运行记录支持的任务结果；如果项目只能被描述成“热门、强大、功能多”，就缩小介绍范围或标注证据缺口。

## 输入

输入契约为 `social_card_fact_base`，内容类型必须是 `repository`。只使用已核验的仓库事实、README、来源 URL、实际运行记录（如有）和明确未知项。

## 输出

输出契约为 `social_card_storyboard`。必须返回严格 JSON；每个页面都要同时包含 `kind` 和 `role`，每个内容块都要包含 `source_refs`。承载核心能力、关键数字、能力对比、操作路径或限制边界的内容块必须输出语义化 `visual` 意图（重点程度、语义色调、受控图标和短徽章），普通背景块可省略；不得输出字号、颜色值、HTML 或 CSS。故事板至少回答：读者要完成什么任务、项目能产出什么可见结果、核心能力如何工作、如何开始、适合谁以及有什么限制。

封面标题需要具体说清任务或输入与结果/问题；可以把项目名作为副标题或辅助识别。只有证据支持时才使用“一条命令”“免费”“本地离线”“几分钟”等承诺。不要用 Star 数、榜单名次或“神器/封神/天花板”代替工具价值。封面提出的结果必须在后续页用对应来源解释或演示。

不得虚构体验、效果、性能、价格、权限、Star、开源协议或安装命令。不得输出发布文案、HTML、CSS 或截图指令。公共输出、证据、密度和降级规则由固定运行时注入，类型页序与仓库原型规则见 `references/storyboard.md`。
