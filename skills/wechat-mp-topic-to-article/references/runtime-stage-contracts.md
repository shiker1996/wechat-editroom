# 成稿运行阶段契约

此文件与 article-pipeline.mjs 中的 ARTICLE_STAGE_CONTRACT 同步。自动成稿链有五个记录阶段：事实基座、直写、审稿、按需字数调整和标题锁定。锁定简报作为输入，不另记为执行阶段；不生成独立大纲，也不设置全篇编辑或表达精修阶段。历史文件名 `05-full-edited.md`、`05-humanized.md` 仍写入透传副本以兼容旧产物消费者。

~~~text
locked-brief + fact-base → drafting → review → length-adjustment → title-lock
~~~

选题时效、近期触发事实和问题可回答性必须已由选题漏斗确认。成稿链沿用锁定简报，不重做选题资格判断。

## fact-base

只根据锁定事实、作者观点和来源正文建立事实基座，不使用模型常识补齐日期、数字、人物行为、任职经历、合同细节、引语或来源。输出 02-fact-base.json 与 02-publication-claim-register.json。verified 只表示来源直接支持该主张；高影响主张没有可靠证据时应收窄、删除或停止。

## drafting

锁定简报中的 `article_type` 直接写入提示词，并用对应类型说明调整表达；不再选择独立主写技能。写作输入是锁定简报和事实基座；流程不生成、传递或等待 02-outline.md。根据简报的核心问题、事实关系和读者任务自行安排文章结构。使用有依据的事实和观点，来源自然归因，不重复解释同一边界。沿用已确认的近期事实与角度，不扩成无依据的泛议题。输出完整 Markdown 正文；文章标题由后续 `title-lock` 阶段生成。

## review

同时使用总契约、锁定简报中的文章类型和 article-reviewer 检查事实支持、事实与判断边界、推理、标题承诺、读者影响是否兑现、结构是否服务主线及发布风险。初次审稿输入为初稿；返修按问题定位处理，最多自动修订两轮。门禁通过时原样保存审稿稿；问题未解决时保留问题并标记待编辑。审稿不重新做时效筛选，只确认稿件是否忠实于锁定简报。

## length-adjustment

仅当正文超出当前字数范围时运行。按目标和范围压缩重复内容或补足已有事实支持的解释；保留标题、关键事实、来源、作者立场和风险边界。调整后重新检查字数与受影响事实，不生成新事实。

## title-lock

直接依据锁定简报、事实基座、发布主张登记和当前文章生成候选并锁定唯一发布标题。程序将标题写入文章唯一 H1，并生成 03-titles.md 与 03-title-lock.json。标题承诺必须由正文兑现；锁题后不得因普通润色修改标题。

## 自动链之后的可选操作

视觉规划只在锁定简报明确需要且文章存在理解增量时运行。发布合规扫描在交付前执行；发现问题时定向修复并复审。当前自动 article-pipeline 不执行 SEO 改写，SEO 技能只能作为单独授权的后续操作，且不得重开选题或添加未经核验主张。
