# 见字桌面工作区极简化设计

> 状态：Phase 1、Phase 2 已实施；Phase 3 已收敛为采集双栏工作区；Phase 4 已完成交互收口首轮，待桌面窗口视觉验收
>
> 日期：2026-09-10
>
> 目标：将当前偏网页导航和内容堆叠的界面，收敛为稳定、低打断、可持续操作的桌面工作区。

## 1. 核心判断

当前界面的问题不是功能不足，而是功能入口、装饰性内容和状态信息同时暴露，导致用户每次进入页面都需要重新寻找下一步。

本次改造不以“换一套皮肤”为目标，而是调整信息架构：

> 从“页面集合”改为“几个长期驻留的工作区”。

第一阶段保持现有采集、写作、图文、发布能力不变，只减少入口、合并页面、稳定布局和降低视觉噪音。

## 2. 设计原则

| 原则 | 落地要求 |
| --- | --- |
| 工作区优先 | 优先在当前工作区切换对象和状态，减少整页跳转 |
| 信息密度 | 用列表、表格、分栏承载信息，减少大面积装饰卡片 |
| 空间稳定 | Sidebar / Main / Inspector 各司其职，位置不随页面变化 |
| 快捷操作 | 鼠标操作完整，常用动作提供快捷键和命令面板 |
| 状态可见 | 保存、运行、同步、失败状态在固定位置持续可见 |
| 少打断 | 优先使用抽屉、内联编辑和 Undo，减少 Modal |
| 布局灵活 | Sidebar、Inspector 可收起；主要面板可调整宽度 |
| 渐进复杂 | 默认只显示核心信息，高级配置放入详情或“更多” |

## 3. 目标布局

```text
┌────────────────────────────────────────────────────────────┐
│ 工作区名称 · 当前批次       已保存       主要操作       ⋯ │
├──────────────┬──────────────────────────────┬──────────────┤
│ Sidebar       │ Main                         │ Inspector    │
│              │                              │              │
│ 今日工作      │ 当前任务、列表、编辑器、结果      │ 当前选中对象   │
│ 采集          │                              │ 属性与配置     │
│ 写作          │                              │ 运行状态       │
│ 发布          │                              │              │
│ 资产          │                              │              │
│              │                              │              │
│ 扩展与设置    │                              │              │
└──────────────┴──────────────────────────────┴──────────────┘
```

### 3.1 Sidebar

- 默认宽度约 208px；支持收起为窄栏。
- 只承载工作区入口，不承载当前对象的操作按钮。
- 侧栏顶部保留品牌和收起按钮。
- 底部集中放置扩展、帮助和系统设置。

### 3.2 Main

- 承载当前工作区的主要任务。
- 同一工作区内切换批次、对象和视图，不把每个状态拆成独立页面。
- 页面首屏只保留一个明确的主要动作。

### 3.3 Inspector

- 默认收起，选中对象或点击“详情”时展开。
- 承载配置、元数据、运行记录和高级操作。
- 不把大量配置直接铺在 Main 区域。

## 4. 一级信息架构

当前多个业务分组收敛为六个工作区：

| 工作区 | 合并内容 |
| --- | --- |
| 今日工作 | 工作台、当前批次、待处理任务、最近活动 |
| 采集 | 采集源、批次采集、热点全景、采集结果 |
| 文章生产 | 文章选题、素材、编辑、公众号排版、封面 |
| 图文生产 | 图文选题、工具图文、自定义图文、事件图文 |
| 发布 | 发布中心、发布状态、复盘数据、内容反馈 |
| 资产 | 文章、图文、热点、产物和任务日志 |

底部保留三个低频入口：

- 扩展与定制；
- 系统设置；
- 帮助与首次使用说明。

原有页面不立即删除，先作为工作区内的视图或 Inspector 内容迁移。迁移完成后再删除旧入口，避免破坏已有链接和用户习惯。

## 5. 页面设计

### 5.1 今日工作

首页从宣传式 Dashboard 改为“今日任务台”，只保留：

1. 当前批次及进度；
2. 下一步主要操作；
3. 待处理失败；
4. 最近编辑内容；
5. 最近运行记录。

首屏只允许一个主要按钮，例如：

```text
当前批次：2026-09-10
采集状态：已完成  ·  待处理 2 项

[继续当前批次]
```

去除或折叠以下内容：

- 大面积装饰型主视觉；
- 与当前任务无关的累计指标；
- 重复表达同一状态的多组卡片；
- 同时出现的多个“开始/新建/快速”按钮。

### 5.2 采集工作区

```text
左：采集源配置
右：采集源列表、筛选、测试与启停
```

采集源列表直接显示就绪、未配置、运行中和失败状态。未就绪来源不进入批次默认选择，也不通过失败任务打扰用户。

### 5.3 写作工作区

```text
左：选题 / 素材
中：文章或图文编辑器
右：文章属性、事实检查、排版和交付
```

素材、文章、图文之间通过当前对象切换，不为每个生产步骤创建新的全屏页面。

### 5.4 发布工作区

```text
左：待发布内容
中：预览
右：发布配置、校验结果和状态
```

发布失败、需要补充配置和已发布状态都在右侧状态区显示，不使用连续弹窗提示。

## 6. 顶部栏规则

顶部栏只保留四类信息：

- 当前工作区或对象名称；
- 当前批次；
- 保存/同步/运行状态；
- 一个主要操作和一个更多菜单。

推荐结构：

```text
采集工作区 · 2026-09-10 批次
已保存                         [开始采集] [⋯]
```

以下操作不再全部平铺在顶部：

- 快速记素材；
- 突发热点；
- 新建批次；
- 首次使用说明；
- 低频导出和维护操作。

它们进入命令面板、更多菜单或当前工作区内的上下文操作。

## 7. 交互规范

### 7.1 操作层级

- 每个页面最多一个 Primary Button。
- 次要操作使用 Ghost Button 或文字按钮。
- 破坏性操作放入更多菜单，并提供确认或 Undo。
- 同一动作不同时出现在顶部、卡片和底部三个位置。

### 7.2 状态层级

统一使用以下状态：

```text
未配置 → 就绪 → 运行中 → 已完成
                    └→ 失败 / 待处理
```

状态必须同时具备：颜色、文字和可执行下一步，不能只依赖颜色。

### 7.3 减少打断

- 编辑配置：右侧 Inspector 或抽屉；
- 修改成功：轻量 Toast，可撤销；
- 运行失败：页面内错误条和失败列表；
- 复杂流程：工作区内分步，不连续弹 Modal；
- 离开未保存内容：统一使用顶部状态和一次确认。

### 7.4 键盘效率

第一阶段提供：

- `Ctrl+B`：收起/展开 Sidebar；
- `Ctrl+K`：打开命令面板；
- `Ctrl+S`：保存当前对象；
- `Esc`：关闭 Inspector、抽屉或命令面板；
- `Ctrl+/`：查看快捷键。

## 8. 视觉约束

### 8.1 颜色

- 基础层使用暖灰纸白、灰绿文字和低饱和分隔线；
- 深石墨色只用于侧栏、主按钮、运行台和关键工作区；
- 雾红：主要动作和错误；
- 浅鼠尾草：成功和就绪；
- 沙色：待处理和警告；
- 状态色只在需要行动的地方出现，不作为普通卡片底色铺满页面。

同一屏幕最多使用一个大面积强调色块，不再使用多个高饱和色卡同时抢夺注意力。普通容器优先使用中性色，通过边框、文字和留白区分层级。

### 8.2 内容密度

- 普通列表优先于大卡片；
- 指标只显示与当前任务直接相关的指标；
- 长文本默认折叠；
- 二级说明使用辅助文字，不与主标题竞争；
- 首页首屏避免超过 3 个信息层级。

### 8.3 装饰

保留品牌识别，但减少：

- 巨型宣传语；
- 无操作价值的背景图形；
- 重复的边框卡片；
- 只起装饰作用的数字和英文标题。

## 9. 分阶段实施

### Phase 1：稳定骨架

1. 收敛 Sidebar 一级入口；
2. 保留当前工作区/主内容/Inspector 三栏结构；
3. 顶部栏只保留标题、状态、主要操作和更多菜单；
4. 将收起按钮固定在 Sidebar 品牌区；
5. 不改变后端接口和业务能力。

### Phase 2：首页减负

1. 移除宣传式 Hero 和重复指标卡；
2. 改为今日任务台；
3. 统一待处理失败、最近活动和当前批次状态；
4. 将低频快捷操作移入命令面板或更多菜单。

### Phase 3：工作区化

1. 采集改为稳定双栏工作区（来源录入、来源台账）；
2. 写作和图文合并为统一生产工作区；
3. 发布改为内容列表、预览和配置三栏；
4. 增加 Inspector 的收起和宽度调整。

### Phase 4：交互收口

1. 统一 Toast、错误条、抽屉和 Undo（保留现有统一 Toast / 确认对话框，并补齐命令操作失败反馈）；
2. 增加命令面板（已完成：Ctrl/Cmd+K、搜索、方向键、Enter、Esc）；
3. 补齐快捷键和焦点管理（已完成：Ctrl/Cmd+1~4、N、K，命令面板关闭后恢复焦点）；
4. 删除已经没有用途的旧页面入口。

## 10. 验收标准

首轮改造完成后，应满足：

- 用户能在 5 秒内找到当前批次和下一步操作；
- 首页主要按钮不超过 1 个；
- 顶部栏显式按钮不超过 4 个；
- Sidebar 一级工作区不超过 6 个；
- 同一功能不同时出现在三个以上位置；
- 配置和详情默认不挤占 Main 区域；
- 采集、写作、发布的主要任务可以在当前工作区连续完成；
- 保存、运行、失败状态无需打开弹窗即可判断；
- 收起 Sidebar 或 Inspector 后，主要任务仍然可完成。

## 11. 非目标

本轮不做以下事情：

- 不重写采集、写作、发布后端流程；
- 不立即删除旧路由和旧页面文件；
- 不引入新的大型 UI 框架；
- 不以增加动画、插画或复杂视觉效果解决信息架构问题；
- 不为了“看起来像桌面应用”而牺牲已有内容密度和键盘效率。
