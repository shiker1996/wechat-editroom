# 橙序员内容策略调整技术设计

> 状态：**阶段 1 进行中（v4 已启用；历史对照与后续阶段待完成）**  
> 范围：账号配比 → 分层素材采集与选题评分 → 内部/外部创作流程 → 四类内容价值判断 → 资源/教程图文  
> 依据：2026-10-22 至 2026-11-21 的 65 篇文章复盘及账号配置建议；该样本用于形成待验证假设，不构成因果证明。  
> 目标分支：`master`（设计时最新提交 `509f847f`）  
> 日期：2026-11-22

## 1. 摘要

本设计拟让工作台更稳定地执行“工具与开源工程实践为主，开发者利益和科技事件为辅”的账号定位，并提升热点评论与资源/教程内容进入候选、完成写作和形成图文的质量。

原有选题评分为 v3；本阶段已按账号策略切换为 v4。素材核验链、内部编辑室亲历依赖确认、外部 Agent 写作指引、资源/教程图文能力与视觉审计继续沿用，本方案不重做这些能力，重点调整：

1. 账号内容配比与素材收集优先级对齐；
2. 让第一梯队直接可写素材和第二梯队事件引子进入不同的选题判断与评分路径；
3. 保持内部编辑室既有亲历确认流程，只补足外部 Agent 对“需要作者实践时如何补料”的约定；
4. 以官方建议的四类内容价值完善热点评论等内容的研判与写作判断，避免把“非工具热点评论”直接判成低价值；
5. 保持资源和教程类贴图优势，优先建设资源包、步骤教程和边界说明的图文选题承接。

评分调整按新素材策略做回放后确定，不直接给工具来源加无条件分；不新增内部编辑室亲历提问，不把作者实测设为所有工具文章的硬要求，不改图文视觉审计规则。

## 2. 证据、观察与待验证假设

### 2.1 样本观察

- 样本覆盖 2026-10-22 至 2026-11-21，共 65 篇文章；存在重复/截断记录，完读率、读者画像和渠道拆分并非每篇都有。
- 阅读前三名及资源型内容对阅读、分享和涨粉贡献集中；这提示资源/工具内容值得继续测试，但不能证明它们必然导致增长。
- 样本报告的整体阅读后关注转化率为 0.41%；这是文章与图文表现需要分开检查的信号，不直接作为系统已有的实时指标。
- 三篇高阅读内容都在晚间发布，但剔除爆款后的早晚场差距小；发布时间只作为分层观察项，不作为首轮评分或候选选择主变量。

### 2.2 配置与实现核对

- 当前账号配置内容配比为工具/开源相关 65%、开发者职场 20%、平台/科技事件 10%、技术认知 5%；建议调整为 60/20/15/5。
- 账号 `scoring.categoryPreference` 中大厂与职场偏好值高于开源类目；账号还有当前管道未消费的 `toolEngineeringBonus` 与 `minimumToolCandidates`。本设计不沿用这两个失效键，改为显式素材策略及经回放校准的评分分项。
- 账号 `scoring.hBase` 中 `github_tool`、`ai_tool_test` 的基线较低。历史类型 H 基线与素材策略适配度 M 不同，是否改 H 需通过回放单独判断。
- `topic-scoring-v3` 已有独立设计与流程契约；本设计提出并行评估 v4 的 M 分项，不覆盖、不迁移或重算历史分数。
- GitHub 项目发现、Feed/RSSHub、Reddit 等采集实现已存在。建议文档中“当前不可用/未认证”的陈述需在实施时通过具体运行配置和源健康记录验证，不能仅凭代码推断。
- 文章链已经有锁定简报、事实基座、联网核验、审稿和 `expected_action` / `ending_payoff` 等字段；教程实操对环境、步骤、成功标准和作者实践证据已有部分约束。
- 社交卡当前生成静态 HTML/PNG、文案和归档产物，并支持结构化视觉方案和程序审计；没有原生投票或发布端交互控件契约。

## 3. 目标与非目标

### 3.1 目标

1. 让账号配比、第一/第二梯队素材定义、选题研判权重和内容选用保持一致。
2. 第二梯队热点必须说明对读者工具、流程、成本、工作或选择的具体影响；无影响转换时不立项或降级。
3. 第一梯队候选获得直接可用性、证据充分性和复现价值评估，不因来源平台标签自动加分。
4. 热点评论按原创判断、事实增量和读者价值评估，不因“不是教程/工具”自动判为低价值。
5. 内部编辑室保留当前依赖亲历的询问与门禁；外部 Agent 在锁定角度确实依赖作者实践时，才补问并等待作者/测试者提供真实材料。
6. 资源包、工具教程和机制对比等贴图方向继续优先，保持现有故事板和视觉审计优势。
7. 变更可回放、可审计，配置和提示词逐步上线。

### 3.2 非目标

- 不把素材来源平台（如 GitHub 或 HN）直接等同于高质量或高分。
- 不将第一/第二梯队写成信源可信度等级；信源可靠性继续独立核验。
- 不为凑候选降低事实、研究依据、风险或通知池门禁。
- 不把内容配比当成严格的单批次数学配额；它是跨周期编辑目标。
- 不新增内部编辑室的亲历依赖提问；不要求所有文章或工具文章都由作者亲自测试。
- 不宣称模型生成的“我试了”是作者实测；只有文章依赖作者实践时才向作者/测试者补充询问。
- 不在静态 HTML/PNG 中实现伪交互投票；平台原生投票需单独确认发布接口能力和授权。
- 不在本方案内建设系列化文章系统、原生投票或复杂增长分析仪表板；互动漏斗改造不属于本轮主范围。
- 不因这份设计文档改变 RSSHub、Reddit、GitHub Token 等运行时凭证。

## 4. 当前链路与缺口

```text
账号画像 / scoring 配置
        ↓
来源采集与热点处理 → 事件/项目候选池 → 研判与评分 v4 → 候选榜单
        ↓                                      ↓
工具/工程简报与事实基座 ← 锁题/编辑确认 → 写作、核验、审稿、标题
                                               ↓
                                           文章交付

故事板与事实基座 → 社交卡 HTML/PNG 与文案 → 视觉/布局审计 → 图文交付

文章发布指标 ──────┐
图文发布指标 ──────┴→ 当前缺少统一、分开的复盘记录格式
```

| 缺口 | 现状判断 | 影响 |
|---|---|---|
| 画像与排序偏好不一致 | `contentRatio` 与 `categoryPreference` 值不完全对应 | 工具定位没有稳定进入候选排序 |
| 素材策略未进评分 | 当前 v3 没有显式区分直接可写工具资源与热点引子 | 第一梯队的可用性和第二梯队的读者利益转换无法按策略评估 |
| 热点评论容易被工具型标准误伤 | 当前流程强调具体读者利益/行动；需检查是否把“无行动建议/无亲历”误当低价值 | 具备事实增量和原创判断的评论可能被过早降级 |
| 内外部亲历补料不对称 | 内部编辑室已有亲历依赖询问；外部 Agent 需核对字段透传和缺料处理 | 外部写作可能因缺少作者实践材料而停错位置，或将公开资料误写成亲历 |
| 资源/教程贴图承接 | 图文视觉链路较完整，选题侧需持续优先已验证的资源、教程优势 | 避免只优化热点评论而稀释已有效的图文方向 |
| 来源可用性需实测 | 有多个采集器代码，但可用性依赖凭证、网络、外部服务与订阅配置 | 先诊断再决定恢复或替代，避免重复造采集器 |

## 5. 方案设计

### 5.1 账号策略与配置对齐

#### 5.1.1 内容配比

建议账号 `contentRatio` 采用：

| 内容方向 | 建议占比 |
|---|---:|
| 工具、开源与工程实践 | 60% |
| 开发者职场与切身利益 | 20% |
| 平台事件与科技商业影响 | 15% |
| 技术认知与原创长文 | 5% |

配比用于账号画像、选题规划和周期复盘，不按每批少量候选硬性截断。建议以滚动 20 篇为主要观察窗口；如果样本量不足，延长窗口并报告样本数。

#### 5.1.2 第一/第二梯队素材与评分公式

素材梯队是选题策略标记，不是来源可信度标记；两梯队都必须独立核实来源。采集查询、项目发现和热点研判应把素材归入以下策略之一：

| 策略 | 典型素材 | 进入文章的方式 | 主要评估项 |
|---|---|---|---|
| `direct_practical`（第一梯队） | GitHub Trending/Release、官网 Changelog、Show HN、awesome 更新、可直接使用的工具/资源、breaking change | 直接回答读者如何获取、使用、复现和判断适用范围 | 直接可用结果、证据/入口可核验、复现或保存价值、限制是否清楚 |
| `event_trigger`（第二梯队） | 大厂/政策/模型/平台事件 | 事件只作引子，须转换为对读者工具、流程、成本、工作或选择的具体影响 | 读者影响是否明确、事实/推理是否成立、是否有原创分析或增量 |

素材层分类应由查询配置和研判产物显式传递，不靠采集器名称推断。遇到混合来源时按文章角度确定策略；无法判定时标为 `unclassified`，采用兼容评分并在产物中告警。

原 v3 没有显式“素材策略适配度”。v4 增加 `M`（material strategy fit，0–100），其分项由所选策略决定，不按来源域名加分：

- 第一梯队 `M_direct`：直接可获得结果、操作/资源证据、可复现路径、使用边界；
- 第二梯队 `M_trigger`：事件事实可靠度、对目标读者的具体传导、独立分析/可验证影响、是否超出新闻复述；
- 任一梯队如果只有热度/知名度、没有相应素材与读者价值，M 低分或不具备入选资格。

建议公式 v4（权重为待回放校准的初始假设）：

```text
A = H×0.50 + B×0.30 + P×0.20
F_v4 = A×0.50 + T×0.20 + J×0.10 + DOM×0.10 + M×0.10 − C
```

`M = M_direct` 或 `M_trigger`。相对于旧公式，从 A/T 组合释放 10 个百分点给 M；H/B/P 内部比例不变。`DOM` 缺失时，对 A/T/J/M 归一化；T 缺失时不产出最终 F。未分类或缺少 M 时使用中性 M=50 并继续按 v4 排序，记录 `materialStrategy=unclassified` / `materialFitSource`。新批次标为 `v4`；已有归档批次不改写。

分项锚点、权重和是否设第二梯队硬门槛必须先对历史批次回放：比较第一/第二梯队候选的排名变化、人工选择一致性、低证据候选是否被放大。若 M 与 T/B 已高度重复或没有稳定增益，先保留分项与审计，不上线新的权重。

热点评论不得因不属于第一梯队自动降分。第二梯队经过读者影响转换、具有高事实支撑和原创解释的评论，可获得高 `M_trigger`；热点热度、情绪张力和标题钩子本身不能替代 M、B 或事实门禁。

### 5.3 采集源健康诊断与增补

先运行一次只读源诊断，按已有订阅与插件健康状态记录：插件 ID/版本、启用状态、最近运行时间、成功/失败状态、条目数、错误类别、凭证是否配置（布尔值，不回显凭证）。诊断结果分开判定：

- 插件/代码缺失；
- 订阅或路由配置缺失；
- 凭证缺失或认证失败；
- 外部服务限流/网络失败；
- 源正常但内容量不足。

若 RSSHub/Reddit/GitHub 源失败，优先修复配置或认证，再评估替代。新增来源优先级：GitHub Trending/Release、官方 changelog/feed、Hacker News Show HN、awesome 项目变更。接入决策标准：可稳定取得标题、URL、发布时间、摘要/描述和来源标识；可去重；失败可观测；不会绕过当前研究依据/事实核验门禁。

GitHub Search 认证与 Search 资源限额需按响应头处理；出现 rate limit 时遵守 `Retry-After` / `x-ratelimit-reset`，有限退避并停止重试，而非无限重放。凭证通过既有安全配置机制注入，不写入仓库、日志或批次产物。[GitHub 认证文档](https://docs.github.com/en/rest/authentication/authenticating-to-the-rest-api)、[GitHub REST 限额文档](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)。HN 可先通过官方 API 验证来源覆盖，再决定是否新增专用插件。[Hacker News API](https://github.com/HackerNews/API)

### 5.4 内部编辑室与外部 Agent 的亲历材料边界

现有 `editorial-room` / `editorial-room-chat` 已会询问“文章是否依赖亲身实践”，并通过 `confirmed_experiences` 和 `experience_required` 保证依赖实践时有可验证材料；该内部流程本次不增加字段、不再加一次提问，也不改变其既有门禁。

外部 Agent 路径当前通过锁定简报和 Skills 执行，需检查简报已声明的 `experience_required` / `decision_source` 并保持与内部含义一致：

- `experience_required=false`：可用已核验公开材料做分析，不要求作者补经历；不得写第一人称亲测或虚构作者决定。
- `experience_required=true`：外部 Agent 先检查现有 `source_materials` / author materials；若没有足以支撑主线的 `author_experience`，明确向用户/作者请求具体实践材料，暂停依赖该实践的成稿，不得用通用经验、网页资料或模型推断代替。
- 只有素材的真实性和归属由作者确认后，才以 `author_experience` 使用；测试环境、步骤、结果、失败边界均由实际操作者提供。若材料补不齐，返回编辑会改为 `experience_required=false` 的公共资料分析，或缩小/取消选题。
- 外部 Agent 的 Skill 负责提出补料问题和保留来源标签；工作台确定性审计继续只检查结构/声明，不声称能验证亲历真实性。

### 5.5 四类内容价值与热点评论判定

用户提供的 2026-07-22 微信内容建议截图归纳了四类方向：

| 内容价值 | 对橙序员的映射 | 研判/写作需要证明什么 |
|---|---|---|
| 标题清晰、主题明确的原创内容 | 工具教程、资源整理、热点评论、技术判断 | 本文自己的问题、命题或组织方式是什么；不能只是换序改写素材 |
| 真人创作与真实分享、友好互动 | 作者实践、真实观察、面向读者的清楚表达 | 有亲历才标 `author_experience`；没有亲历时使用可追溯材料并准确归属；互动服务主题，不靠强制 CTA |
| 对用户有价值、能启发或产生共鸣 | 工具/资源的可获得结果；热点评论的工作、成本、选择、风险或判断增量 | 读者看完多知道什么、能判断什么或解决什么；价值可以是理解，不必强行变成操作建议 |
| 垂直领域经验证的知识分享或真实经验 | 工程机制解释、开源项目分析、AI 工具实践 | 专业/技术主张有证据；实测与一般原理区分；不以专业语气替代证据 |

#### 热点评论的价值门槛

热点或评论不是低价值的同义词，也不能仅凭“读者利益字段不够具体”自动压低所有观点型候选。研判应检查四项：

1. **事实基础：** 关键事实、来源归属、时间和不确定边界清楚；
2. **原创判断：** 提供独立解释、因果链、利益结构、反例或有根据的预测，不是复述热搜；
3. **读者增量：** 对开发者/职场读者解释影响、机制、成本、选择或可观察信号；理解/判断本身可以是收益；
4. **标题与主题兑现：** 标题承诺能在开头和正文中兑现，不靠情绪词/主体知名度充当价值。

把这些维度用于评分与审稿，不要求每篇热点评论都提供“本人亲历”或具体行动方案。缺少实证时，可用可靠公开资料支撑分析并标明边界；若没有事实、原创判断或读者增量，再判为低价值/不立项。

写作流程复核重点：当前锁定简报已包含读者任务、读者后果、判断/行动价值和 `reader_value_type`；检查提示词、内外部 Skills 是否把 `reader_action` 误当成必须的行动建议，或把推荐池工具格式硬套给热点评论。只调整存在误判的规则，保留现有事实核验、来源归属、标题兑现和高风险主张门禁。

### 5.6 资源与教程贴图优势承接

贴图定位继续围绕可保存、可复用的资源和能照做的教程：代码集/模板/清单、工具快速上手、机制对比与适用边界。热点评论只有在图示能增加理解或保存价值时才转成图文，不为了占内容配比把所有热点转卡片。

- 选题/图文规划增加 `cardFit` 判断：可保存资源、可复现步骤、需要图示的结构对比、明确适用边界；判断低时继续走文章或不做图文。
- 资源卡应给可核验的资源入口、收录范围/更新时间、授权或使用限制；不得只拼接项目名称和宣传句。

实现前按这些标识搜索实际消费者：`contentRatio`、`categoryPreference`、`materialStrategy`、`M_direct` / `M_trigger`、`experience_required`、`confirmed_experiences`、`reader_value_type`、`cardFit`。核对内部编辑室与外部 Agent 的输入、门禁、存储和输出，不推断两条路径行为相同。

## 10. 风险与回退

| 风险 | 应对 | 回退方式 |
|---|---|---|
| 来源标签变成来源平台偏置 | `materialStrategy` 表示素材如何服务文章；信源可信度独立评分 | 将策略纠正为 `unclassified`，按 v4 中性 M=50 计算并审查评分理由 |
| 配置修改影响历史排序判断 | 保存版本与回放快照；只影响新批次 | 恢复配置备份；不重写历史分数 |
| 外部 Agent 虚构作者亲历 | 仅在 `experience_required=true` 且材料缺失时暂停并补问；来源层级保持显式 | 返回编辑会改为公共分析或停止成稿 |
| 热点评论被一概判低价值 | 分开检查事实、原创解释、读者增量和建议；无行动建议不等于无价值 | 回退过严的新规则，保留现有审稿门禁并人工复核 |
| 资源/教程方向挤占其他内容且未复现优势 | 将配比作为滚动周期目标，观察各内容类型表现 | 恢复上个配置版本并延长观察窗口 |
| 采集 API 限流或认证失败 | 按限额头处理，有限退避，源级健康报告 | 停用问题源，使用已有人工/订阅来源 |
| 65 篇样本过小或渠道不完整 | 记录分母、窗口、样本量和缺失项 | 延长观察期，不调参数或不作效果结论 |
