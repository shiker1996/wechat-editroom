# MCP 与内部业务流程对齐

> 状态：实施进度记录（2026-11-03）。本文最初是计划，不是当前接口契约；各工具的参数和实际校验以 MCP 工具定义、HTTP 路由及对应 Skill 为准。

目标是让外部 Agent 在不配置见字内部模型的情况下完成工作，同时保留内部模型路径。两条路径目前并非所有业务阶段都共用同一套提示词和状态机。

## 当前实现

| 流程 | 当前行为 | 与内部流程的关系 |
|---|---|---|
| 批次研判 | MCP 可保存标签和事件卡，并通过 `jianzi_research_stage_prepare` / `jianzi_research_stage_submit` 驱动原研判 pipeline；工作台继续执行评分、校验和入池。 | 研判阶段由内部 pipeline 推进，外部 Agent 提供模型输出。 |
| 外部文章成稿 | Agent 抓取候选原文、依据锁定简报和事实材料写作、自审，可选调用本地 Markdown 审计，然后通过 `jianzi_article_document_save` 保存草稿；用户确认后再保存终稿。 | 不经过内部 `runArticlePipeline` 的事实基座、直写、审稿、按需调字数和标题锁定阶段。文章本地审计只给提醒，不替代事实核验或审稿。 |
| 内部文章成稿 | `runArticlePipeline` 记录五个阶段：事实基座、直写、审稿、按需字数调整、标题锁定；自动链不执行 SEO 改写。 | 仅内部模型生成路径执行这条阶段流水线。 |
| 排版、封面、图文 | 外部 Agent 生成设计方案和 HTML 后提交；工作台执行对应的产物校验，图文提交包含故事板页数和浏览器溢出审计，并负责截图及归档。 | 生成模型可以不同；提交侧门禁和归档由工作台处理。 |
| 早报、教程、突发分析、独立审稿及对话 Agent | 仍需按各自 MCP 工具、Skill 和业务入口分别确认覆盖范围。 | 本文不宣称这些流程已与内部实现完全统一。 |

## 后续验证

1. 用独立测试副本通过 MCP、Skill 和 CLI 验证采集、研判、文章、排版、封面和图文的完整交付，并记录实际使用的入口、状态和产物链接。
2. 对研判检查超过 200 条时的分批提交、重复提交和失败恢复；对文章检查草稿/终稿确认次序及失败恢复；对视觉产物检查门禁、截图和归档。
3. 单独核对早报、教程、突发分析、独立审稿和对话 Agent，不以研判或文章链路通过推定其已覆盖。

现行阶段契约见 [成稿运行阶段契约](../skills/wechat-mp-topic-to-article/references/runtime-stage-contracts.md)，外部 Agent 的操作顺序见 [Agent 使用指南](./agent-usage-guide.md)。
